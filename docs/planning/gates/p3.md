**Status:** Implementation complete; review pending

**Owner:** Core maintainer

P3 turns the functional single-component frontend into a maintainable product shell. It does not
use family pilot perfumes or collect baseline outcomes.

| Work package | Required result | Retained evidence |
| :--- | :--- | :--- |
| P3.1 Information architecture | Route-backed participant and manager pages with reload and back-navigation support | Route/component tests |
| P3.2 Identity and capability model | Authenticated identity and evaluator, recorder, and manager capabilities drive navigation and actions | Role matrix and UI/API tests |
| P3.3 Component foundation | Shared layout, form, status, confirmation, and error components | Component inventory and tests |
| P3.4 API boundary | Typed contracts and one loading, validation, and error policy | Build/type evidence and failure tests |
| P3.5 Responsive accessibility | 360-pixel mobile layout, keyboard operation, visible focus, and automated accessibility baseline | Accessibility and viewport report |
| P3.6 Degraded operation | Clear retry and optional-service failure states | Failure-mode tests |

P3 closes when the shell can support feature-level work without adding more workflow logic to a
single application component and all privileged navigation is derived from verified capability.

## Implementation evidence, 2026-09-11

- The former 800-line application component is split into four feature pages, a shared shell,
  typed API contracts, shared application-data and task hooks, and reusable feedback, loading,
  retry, empty, and confirmation components.
- `/calibration`, `/recommendations`, `/ratings`, and `/programs` are reloadable paths and browser
  pop-state navigation is covered by tests.
- The verified `/calibration/access` response and recorder assignments derive displayed
  capabilities. Manager navigation is hidden for non-managers, and direct manager URLs redirect
  without rendering privileged content; server authorization remains authoritative.
- Responsive rules cover 360-pixel layouts, visible focus and skip navigation are present, and an
  automated semantic baseline checks landmarks, control labels, action names, and duplicate IDs.
- Eleven frontend tests cover retained workflows, saved recommendation hydration, routing,
  verified manager navigation, activation confirmation, direct-route denial, retry behavior, and
  the accessibility baseline.
- TypeScript production build, ESLint, Prettier verification, and the frontend test suite pass.

P3 becomes complete after code review, remote CI, and merge evidence are recorded.
