**Status:** In progress; repository rehearsal kit prepared, target execution pending

**Owner:** Core maintainer

P6 is the hard boundary before actual perfume testing. No pilot fragrance is presented and no
family outcome is counted until P6.1-P6.6 all pass and P6.6 records a `go` decision.

| Work package | Required result | Retained evidence |
| :--- | :--- | :--- |
| P6.1 P1 closure | P1.1-P1.10 evidence passes against the release candidate and target topology | Completed P1 gate record |
| P6.2 Authenticated device matrix | Participant, recorder, and manager journeys pass through Authentik/Traefik on supported family devices | [Device/browser matrix](../evidence/p6-device-matrix.md) |
| P6.3 Synthetic rehearsal | Full setup-to-report workflow runs with unmistakably synthetic/demo samples and outcomes, on the exact same participant instrument build F1 will use (R7b must have merged; see `PROJECT-PLAN.md` section 11a). This is a hard gate: P6.3, and therefore P6, cannot close until R7b has merged. The retained evidence must name the exact R7b build exercised (commit SHA and image digests), not just record that R7b has merged | [Rehearsal log and export manifest](../evidence/p6-synthetic-rehearsal.md) |
| P6.4 Quality gate | Accessibility, keyboard, responsive, performance, disclosure, and recovery checks pass on every critical page | [Consolidated quality report](../evidence/p6-quality-report.md) |
| P6.5 Operations rehearsal | Backup/restore, alerts, logs, secret ownership, and printable/manual outage procedure are exercised | [Operations drill record](../evidence/p6-operations-drill.md) |
| P6.6 Readiness decision | Participant/manager instructions and known limitations are reviewed; a decision is recorded and only `go` closes P6 | [Signed readiness record](../evidence/p6-readiness-decision.md) |

Any unmet P6.1-P6.6 result or a `no-go` decision blocks F1, including failures in workflow,
measurement, data integrity, authorization, blind disclosure, accessibility, responsive use,
performance, recovery, or operations. A failed gate returns work to the owning P sprint and
requires rerun evidence.

Any change to the participant-facing instrument build after P6.3's rehearsal has run, including a
change to an already-merged R7b, voids P6.3: the rehearsal must be repeated against the changed
build before F1 begins. This holds regardless of whether the change lands before or after P6 has
otherwise closed. The rule exists because F1's initial four evaluators cannot redo their one blind
pass through the instrument once it starts, so a rehearsal that validated a build F1 will not
run proves nothing about the instrument that matters.

## Facilitated-format scope for P6.2 and P6.3 (added 2026-11-25)

F1 may run as the six-evaluator facilitated format decided on 2026-11-24 (see the [F1 gate](f1.md)). In that case
P6.2 and P6.3 must cover it; a rehearsal of only the one-evaluator, on-screen path does not rehearse the instrument
F1 will use. This section is a scope requirement, not evidence: nothing here is recorded as done.

**P6.2 additions.** The device matrix covers the single recorder login that transcribes all six evaluators' paper
sheets (one recorder session, one evaluator at a time, on the facilitator's device), and the manager actions the
format needs: session-plan preview, the non-blind call, program checkpoints, the readiness view and the household
reveal.

**P6.3 additions.** The synthetic rehearsal must run the paper plus transcription flow in the six-person format:

- six synthetic evaluators, shared triples with per-session Latin-square rotation and random codes, printed
  [session sheets](../../facilitated-session-sheet.md) and [conditions slips](../../facilitated-conditions-slip.md)
  filled in on paper, and the facilitator transcribing every sheet through one recorder login;
- the holder flagged non-blind, a checkpoint created for every enrollment before any holdout is touched, a
  household reveal after the holdouts, and the facilitator spray-sheet generator exercised on a synthetic mapping
  kept outside the repository;
- confirmation of the **provisional 2-minute spray-to-first-smell ceiling** (owner decision 2026-11-25, replacing the
  earlier 5 minutes): measured with six evaluators passing one blotter round in a fixed seat order, with the actual
  sprayed, first-smelled and column-finished times and any breach recorded as a deviation. The rehearsal must test
  whether six people can rotate within 2 minutes, **including at least one replacement blotter** (a new blotter of
  the same sample, same blind code, sprayed when the window would be exceeded, with each sheet's Time sprayed being
  the spray time of the blotter that evaluator smelled), and must record how often a replacement was needed. The
  2 minutes is a working value, not a researched one; the rehearsal confirms it or replaces it, and a changed value
  is recorded in the F1 pre-exposure declaration. The 2 minute clean-air interval between samples (ADR-005) is a
  different number and is checked separately;
- confirmation of the **group blotter procedure**: one physical blotter per sample passed round the six evaluators one
  blotter at a time, shared blind codes and order, the `group_shared_blotter` flag present on every session, and
  paper plus transcription of the resulting sheets (each evaluator's own Time sprayed entered). Spraying all 18
  blotters at once is not the procedure (too strong a smell). The rehearsal confirms the procedure or records a
  different one;
- the **group safeguards (#221) deliberately attacked**, each recorded in the rehearsal log: (1) enter one evaluator's
  sheet under the wrong evaluator in group mode and record whether anything catches it (the blind-code guard is not
  expected to, because the code is shared); (2) withdraw one of the six evaluators and record what happens to the
  household reveal (no withdrawal path exists, so this documents the gap rather than passing it); (3) a holdout column
  whose times pre-date the checkpoint, which the server must refuse with a 422; and (4) the program-wide gate itself,
  with holdouts refused until every enrollment has a checkpoint. These do not exercise the facilitator's own rule of not
  smelling a holdout before the checkpoints exist, which is procedure and is observed, not tested;
- confirmation of the **paper-retention period**: the run sheet applies the consent text's period (the evaluation
  database is kept 12 months after the evaluation ends) to sheets, slips and scans, which is an inference awaiting
  owner confirmation. The rehearsal records the period the owner fixes and shows that scans can be stored and later
  destroyed together with the database and its backups.

**The merged code is the rehearsed instrument.** The paper sheet and conditions slip each carry a version id, and
the participant-facing build is pinned as before. A change after P6.3 has run to the sheet, the slip, the
transcription or wizard screens, enrollment, the holdout gate or the reveal voids the rehearsal for the changed
parts and requires a re-run before F1, on the same rule as above for any participant-instrument change. So the
facilitated-format work items listed in
[PROJECT-PLAN.md section 11a](../PROJECT-PLAN.md#f1-facilitated-format-work-items-decided-2026-11-24) must be merged
before P6.3 runs. As of 2026-11-25 the session-scoped wizard (#216) and the transcription timing work (#218) are
merged; the group blotter code pull request (#220) and the group safeguards pull request (#221) are merged too (see
the plan). Sheet version `facilitated-session-sheet v2.0` is the version P6.3 must rehearse.

## Interim evidence, 2026-09-18: production deployment incident

An unplanned production deployment of `fragrance.williamshome.family` through Authentik/Traefik on
`docker-host` returned 502s, then went fully offline after a partial fix. Three chained defects
were found and fixed, each in its own PR:

- Wrong Docker build stage published (frontend served a non-production image), fixed by PR #100.
- A Trivy registry-scan CI bug blocked publishing the corrected image, fixed by PR #101.
- The container `HEALTHCHECK` used a hostname that resolved to an IPv6 address `wget` could not
  reach, so Docker never reported the container healthy even after the image fix landed, fixed by
  PR #102.

**Relevance to this gate:** this is a real exercise of the Authentik/Traefik target topology named
in P6.2, and it happened outside any planned rehearsal. It does not substitute for P6.2's device
matrix, and it does not touch P6.3-P6.6 at all (no synthetic data, no accessibility/keyboard/
responsive pass, no operations drill, no readiness decision). Recorded here so the gate's evidence
trail includes it rather than leaving a real deployment event undocumented.
