## Identity-resolution pipeline hardening, 2026-09-12

Prompted by "how does the *system* (not an ad hoc research pass) resolve these gaps in
production," this turned the manual disambiguation work above into repeatable mechanisms:

- **Fixed `ParfumoScraper.search()`** to use the real livesearch endpoint found during the V3.1
  resolution work (see the P1.1 section above), and extended `SearchResult` with `concentration`
  and `year`. `import-data parfumo-search` now prints both for every candidate, and refuses
  `--import-first` outright when multiple candidates share a name (added `--select N` for that
  case) - the same class of case as the Caron Aimez-Moi finding, now caught by the tool itself
  rather than requiring external research to notice.
- **GTIN/barcode capture**: `fragrance_rater.utils.gtin` implements GS1 check-digit validation,
  shared by `scripts/validate_calibration_manifest.py` (new optional `gtin` manifest field),
  `ParfumoScraper._extract_gtin` (reads `meta[itemprop='gtin13']` when Parfumo publishes one,
  validating before trusting it), and the live API's `MembershipInput.gtin`. A barcode read off
  the physical bottle is the strongest identity signal available - manufacturer-assigned per
  exact SKU, unlike any text-based comparison - so `CalibrationService` rejects a
  manager-entered GTIN outright if it contradicts the fragrance's own recorded source evidence,
  and accepts it (recording it on the membership) when no conflicting evidence exists.
- 642 unit tests (up from 617), Ruff, Ruff format, BasedPyright (0 errors), and Bandit are clean
  on every changed file.

## Fragella reference lookup, 2026-09-12

The product owner authorized Fragella's 20-request/month free tier as a capped backup for
exactly the gaps the pipeline above still leaves to a human: a same-name ambiguity Parfumo's own
search doesn't resolve, or a concentration/year Parfumo doesn't publish.

- `fragella_client.py` (`FragellaClient`) and two new CLI commands, `import-data
  fragella-lookup`/`fragella-usage`, are an operator-invoked, decision-support lookup only -
  nothing they return is written into the `Fragrance` catalog or a `SourceSnapshot`. See
  ADR-002's 2026-09-12 amendment for why this does not require its own reuse-rights review the
  way adopting Fragella as a stored source would.
- Quota discipline: the client validates query length/limit client-side before spending a call,
  surfaces Fragella's own HTTP 429 as the quota-exhausted signal rather than tracking usage
  locally (a local counter could drift from Fragella's own billing truth), and exposes
  `/usage` via its own explicit command rather than calling it automatically before every lookup,
  since whether it counts against the same quota is undocumented.
- **This integration is built from Fragella's published API documentation
  (<https://api.fragella.com/docs.html>), not a live authenticated response** - no API key was
  available while building it. Response field names/casing and the unpaginated response envelope
  are the documentation's best description, not something fetched and inspected directly, unlike
  every Parfumo selector in this project. Smoke-test `search()`/`usage()` against a real key
  before relying on this for an actual gap-filling decision, and add regression fixtures from
  that real response once available - see `fragella_client.py`'s module docstring.
- 660 unit tests (up from 642), Ruff, Ruff format, BasedPyright (0 errors), and Bandit are clean
  on every changed file.

## Fragella manager-UI run button, 2026-09-12

Extends the CLI-only lookup above with a manager-facing "run" action on the Program setup page,
so a manager can fill holes across a program's memberships without a terminal:

- New `fragella_lookups` table (Alembic `a1b2c3d4e5f6`) and `FragellaLookupService` record every
  attempt (success or error) against a fragrance, keyed so the manager UI can show which
  memberships have never been checked ("fill holes") without spending a request just to find out.
  This is explicitly not `SourceSnapshot`-equivalent adopted evidence - see the model's own
  docstring and ADR-002's amendment; nothing here is ever written into `Fragrance` columns or a
  membership's `identity_evidence`.
- New manager-only API: `POST /calibration/programs/{id}/members/{id}/fragella-lookup` (runs/
  re-runs a lookup for one membership) and `GET /calibration/fragella/usage` (quota check, called
  only on manager request, never automatically). `GET .../members` now embeds each membership's
  latest lookup (or `null` if never checked).
- Program Setup page: each membership shows "Run Fragella check" (never checked) or its recorded
  result plus a confirmed "Re-check Fragella" action (spending another of the 20 monthly requests
  is deliberate, not a stray click) and results are always labeled reference-only. A "Check
  Fragella quota" button surfaces remaining requests on demand.
- 674 backend unit tests (up from 660) and 28 frontend tests (up from 27) pass; Ruff, Ruff
  format, BasedPyright (0 errors), Bandit, ESLint, Prettier, and the production TypeScript build
  are clean on every changed file. Updated the
  [P5 manager disclosure matrix](../evidence/p5-manager-disclosure.md) for the new manager-only
  surfaces.

## P1.9 evidence, 2026-09-12

- Fixture provenance: two live, publicly reachable Parfumo perfume pages (Creed Aventus, Chanel
  Bleu de Chanel) were each fetched once via an ordinary HTTPS GET - the same access any visitor's
  browser performs - to confirm current markup structure. Neither page's content is stored,
  committed, or redistributed in this repository; every fixture in
  `tests/unit/test_services/test_parfumo_scraper.py` is hand-authored synthetic HTML using
  fictitious brand/fragrance names, modeling the confirmed CSS classes and `data-*` attributes
  (`.barfiller_element.rating-details[data-type]`, the "Also liked" sidebar, the `.p_con`
  concentration trigger). The module docstring records this provenance in place.
- Parser coverage added for the required categories:
  - **Requested metrics**: `_extract_metrics` reads the five per-dimension community ratings
    (scent, longevity, sillage, bottle, value for money) from their scoped score/count elements.
  - **Status**: `_extract_production_status` reads Parfumo's own "still in production" / "no
    longer in production" sentence; anything unrecognized stays `None`.
  - **Similar fragrances**: `_extract_similar_fragrances` reads the sidebar "Also liked" list
    (real anchors); the in-page "Smells similar" widget is confirmed AJAX/JS-only
    (`data-p_id`/`data-s_id`, no `href`) and is not scraped.
  - **Related versions**: confirmed AJAX-only on the live site (`getConcentrationsPopup()`); no
    `related_versions` field was added, and a regression test
    (`TestParfumoScraperConcentrationVariantLimitation`) asserts none is fabricated, consistent
    with the "no guessed fragrance concentration or version" release-blocking invariant.
  - **Missing fields**: a fixture with no rating/description/similar sections confirms every new
    field defaults to empty/`None` rather than raising or guessing.
  - **Unknown concentration**: covered by the existing source-snapshot regression test; unchanged.
  - Along the way, fixture verification against the real nested rating-block markup found that
    `_extract_rating`'s prior whole-block-text regex could fuse the score and vote count into one
    bogus number on that markup shape; it now prefers the scoped score/count elements, with the
    original flat-text form kept as a fallback (both are regression-tested).
- 66 scraper tests and the full 617-test unit suite pass; Ruff, Ruff format, BasedPyright, and
  Bandit are clean on the changed files. This is the P1.9 baseline the Fragella sections above
  grew from ("642 unit tests (up from 617)", then 660, then 674); it predates that work
  chronologically even though it is recorded last in this document.
