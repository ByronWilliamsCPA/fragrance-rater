**Status:** Complete

**Owner:** Core maintainer

P4 delivers every task a family evaluator needs before pilot use. Development and verification
use synthetic or demo records only.

| Work package | Required result | Retained evidence |
| :--- | :--- | :--- |
| P4.1 Home and assignments | Current work, progress, and safe next action are understandable without internal IDs | Usability checklist and UI tests |
| P4.2 Ordinary encounters | Search, entry, validation, history, and correction are complete on mobile and desktop | End-to-end encounter test |
| P4.3 Blind calibration | Guided blotter/skin entry, progress, locking consequences, and reveal eligibility | End-to-end blind-flow test |
| P4.4 Recommendations | Saved/new sets, explanations, and one-tap interest work without duplicate impressions | Recommendation UI tests |
| P4.5 Follow-up outcomes | Sampling state, unavailability, outcome link, would-wear, would-buy, and revision history are usable | End-to-end follow-up test |
| P4.6 Interruption safety | Reload, retry, stale data, validation errors, and home-network interruption preserve understandable state | Recovery test report |
| P4.7 Disclosure | Experimental metadata stays concealed | [Matrix](../evidence/p4-participant-disclosure.md) |

P4 closes only when a participant can complete the entire journey without API tools, database
access, or copying UUIDs.

## Implementation progress, 2026-09-11

- The new home route summarizes each accessible assignment with named evaluator/program context,
  blind-lock progress, and the next safe action without displaying internal identifiers.
- Ordinary encounter history now supports correction of rating and observations while preserving
  the original fragrance and encounter date.
- Recommendation runs return their append-only response histories. Participant cards can append
  interest, sampling, unavailability, wear, buy, and matching ordinary or revealed controlled
  outcome links, and display revision history after reload.
- Calibration now requires explicit confirmation before finalizing a skin plan, locking a blind
  stage, or revealing identities.

- Recommendation cards request optional personalized explanations and fall back to a deterministic
  affinity explanation without blocking core use when that service is unavailable.
- Guided calibration states explain remaining blotter work, skin-plan finalization, remaining skin
  work, and reveal eligibility. Every irreversible transition has context-specific confirmation.
- Twenty-six frontend tests cover home progress, ordinary entry/correction, blind capture and
  reveal guidance, recommendation persistence and replacement failure, stale responses,
  follow-up outcomes, optional explanation degradation, routing, retry, and accessibility.
- Focused API lifecycle tests cover participant disclosure/reveal and append-only response history.
  The TypeScript build, ESLint, Prettier, Ruff, BasedPyright, security hooks, and documentation
  checks pass.
