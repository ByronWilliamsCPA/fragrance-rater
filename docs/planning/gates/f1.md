**Status:** Planned. The owner recorded a P6.6 `go` on 2026-11-27 with the P6.3 rehearsal waived and some P6 evidence
unrecorded (see the [readiness record](../evidence/p6-readiness-decision.md) and the [P6 gate](p6.md)). Program `v3.2`
is activated with six evaluators enrolled and shared blind codes in place (sign-off 19). The first sitting is not yet
complete, and nothing in this page is F1 evidence.

**Owners:** Product owner and core maintainer

F1 is the first use of actual pilot perfumes. It validates product usability and establishes
descriptive baselines; it is not evidence that a recommendation algorithm is accurate.

Before the first exposure, record the pilot dates, evaluators, exact physical samples, algorithm
and prompt versions, candidate strategy, source snapshot, exclusions, support procedure, and
stopping conditions in a private evidence location. Also name, in that declaration, the person who
retrieves the blind-to-identity mapping and labels physical samples, and confirm whether that
person is also one of the evaluators (a manager who is also an evaluator cannot be made blind
by software; see the note below). The facilitated format below has its own, stricter declaration.

| Evidence | Required contents |
| :--- | :--- |
| Use and support log | UI-only task completion, abandonment, errors, help required, connectivity failures, and recoveries |
| Measurement export | Eligible impressions, explicit responses, interest, sampling, liking, wear/buy, unavailability, coverage, variety, and every denominator |
| Provenance record | Population, window, versions, strategy, filters, exclusions, source snapshot, and export hash |
| Blind-baseline instrument completeness | Participant-instrument version (R7b build) recorded on the activated `Program`; per-field non-null counts across all evaluators' pre-reveal rows (four in the original design, six in the facilitated format), with denominators, for every first-blind-moment field named in `preference-prediction-data-capture-assessment.md` section 13.13 and `PROJECT-PLAN.md`'s R7a/R7b rows; `season_fit`/`setting_fit` completeness is counted against eligible skin-stage rows only, blotter rows excluded, using the same denominators as the R7b export; count of deviation/quality flags; count of consent records |
| Pilot review | Usability findings separated from fragrance and algorithm outcomes; small-sample limits stated |
| Decision | Record proceed to D1, revise a P3-P6 workflow, extend the declared pilot, or stop |

The evaluator who also holds the identity mapping is not blind for the duration of F1. That
evaluator's rows carry a quality flag marking them non-blind and are excluded from blind-baseline
model training, but remain in evaluation: per-evaluator metrics still report that evaluator, and
the pooled repeat benchmark is reported both ways, as 18 pairs excluding that evaluator and as all
24 pairs including them for four evaluators (30 and 36 for the six-evaluator facilitated format, see
below; see the [ADR-009 2026-09-21
amendment](../adr/adr-009-prospective-evaluation-and-checkpoints.md#2026-09-21-amendment-mapping-holder-evaluator-excluded-from-training-retained-in-evaluation)).
The other evaluators' data is unaffected. This is a structural limitation, not a defect to fix in
software, and must be recorded in the pre-exposure declaration rather than discovered afterward.

## Facilitated six-evaluator format: additional pre-exposure declaration

Decided by the product owner on 2026-11-24 (see the [ADR-005 amendment](../adr/adr-005-controlled-calibration.md#2026-11-24-amendment-six-evaluator-facilitated-f1-format)
and the [ADR-009 amendment](../adr/adr-009-prospective-evaluation-and-checkpoints.md#2026-11-24-amendment-six-evaluator-facilitated-f1-format)).
If F1 runs in this format, the private pre-exposure declaration must also state each of the following
before the first exposure. This list is a requirement on the declaration; none of it is evidence yet, and
this section does not change the gate status above.

1. **Evaluators.** Exactly six, named, with the date of each one's consent recorded in the application.
   Consent is recorded once before session 1 with the evaluator present, persists per scope until
   withdrawn, and is not repeated per sitting. State which evaluators are new to fragrance (three are
   expected).
2. **Mapping holder.** One named person who evaluates and is flagged non-blind, and who also facilitates (helps the
   other five keep their blotters, trays and sheets organized, enforces silence and clean-air intervals),
   transcribes, verifies and controls the reveal for the whole program. The holder does not evaluate during the
   other five evaluators' sessions; the holder's own evaluations run in separate sessions. State that the
   holder's observations are single-blind with observer cues, that the holder's rows carry the non-blind quality
   flag, and that they are excluded from blind-baseline training and retained in evaluation. Record the holder's
   **enrollment id** and the **date** the `POST /api/v1/calibration/enrollments/{id}/non-blind` call was made, which
   must be before the first exposure. The holder's name stays in the private declaration, not in the repository.
3. **Recording identity.** One recorder login transcribes all six evaluators' paper sheets. State that
   this departs from the usual separation of evaluator and recorder identities, and that the evaluators
   themselves have no logins and no phones during sessions.
4. **Sheet, slip and guide versions.** Name the paper session sheet's version id (for example
   `facilitated-session-sheet v2.2`), the separate session-conditions slip's version id (for example
   `facilitated-conditions-slip v1.0`) and the evaluator property guide's version id (for example
   `facilitated-property-guide v1.0`, a reading aid that adds no recorded field and changes no scale), exactly as
   printed, and state that the sheet and slip ids equal the ids rehearsed in P6.3. The owner reviewed and accepted
   the handout wording on 2026-11-25 (the formal sign-off record belongs in the private declaration). The handout is
   outside the P6.3 instrument, which rehearses the sheet and slip and not the handout, so a later handout wording
   change does not void P6.3, provided it adds no recorded field and the declaration names the version id actually
   used.
   If sheets of two versions were used in one program, name both. Owner decision (2026-11-25): a change to the
   participant build, the session sheet or the conditions slip after the P6.3 rehearsal voids that rehearsal for the
   changed parts.
5. **Timing.** No fixed elapsed interval. The declaration records the provisional spray-to-first-smell
   ceiling of **2 minutes** (changed from 5 minutes by the owner on 2026-11-25 and kept at 2 minutes after the group
   attempt), counted from an evaluator's own spray of their own blotter to that evaluator's own first smell, which is a
   working value to be confirmed in P6.3, and states that
   actual sprayed, first-smelled and column-finished times are recorded and that a breach is recorded as a
   deviation, not dropped. The declaration must keep this separate from the clean-air interval between samples (at
   least 2 minutes, about 5 after a persistent sample, ADR-005, unchanged), which is a different number. Also fix the **spray distance and spray count** (for example a stated distance in centimetres and a
   stated number of sprays per blotter), the same for every blotter and an instruction to each evaluator. The
   repository defines neither, so the declaration is where they are set; do not start without values. The owner
   decided on 2026-11-25: one spray from about 15 cm (6 in), pointed away from faces and other blotters, the same for
   every blotter. State the **blotter mode** as **individual** (one blotter per evaluator per
   sample, each evaluator spraying their own; the program's `blotter_mode` is `INDIVIDUAL`). State the
   **fresh-blotter rule**: if an evaluator's own 2 minute window passes before they have smelled the blotter, they
   spray a fresh blotter of the same sample (same blind code) and write the new spray time, and each sheet's Time
   sprayed is the spray time of the blotter that evaluator smelled. Group blotter mode is built and merged but not
   used by F1 (the owner's physical attempt on 2026-11-25 got two evaluators through in two minutes), so no group flag or
   seat order applies. (Amended 2026-11-27: the shared blind codes of sign-off 19 are a separate, later change made in
   individual mode, and the consequences accepted for them are listed there.)
6. **Novices.** Everyone is included and repeat consistency is reported descriptively. No exclusion
   threshold is declared or applied; the declaration must say so, so that none is added after outcomes.
7. **Skin.** Only the non-blind holder carries a skin plan; the other five finalize an intentionally empty
   plan and are skin-absent by design. Skin tests run on their own day and workflow, one new application per
   evaluator per day. Completeness denominators for skin-stage fields count only evaluators with a skin plan.
8. **Phase order and reveal.** All six complete baseline including hidden repeats; skin plans finalized;
   a checkpoint per enrollment; holdouts; then one household (program-level) reveal. All six evaluators are
   captured before the next session starts.
9. **Labels and order.** One shared blind code per physical sample, equal to the label on the atomizer and the same
   for all six evaluators (decided and implemented 2026-11-27, sign-off 19; no label scheme is stored, and the stored
   marker of a shared code is `shared_blind_code`). This replaces the earlier text of this item, which named random
   blind codes that were each evaluator's own. Shared triples with per-session Latin-square rotation
   (`shared-triples-latin-rotation-v1` with the program's `blotter_mode` `INDIVIDUAL`), and the program's session
   composition. *Where each is recorded (corrected 2026-11-27; this item earlier said the composition was recorded with
   the manifest hash):* the database records, on each enrollment, a template digest (SHA-256 over the session
   composition) and, when the server generated the template, its generation seed, together with the evaluator's
   rotation (`Enrollment.randomization_seed`); the manifest hash (`3bc3edc9` as of 2026-11-24, re-check) is not stored
   in the database and is held in the owner's local draft metadata, so the declaration states both and does not treat
   one as a proxy for the other. Per-evaluator holdout eligibility
   (the H02 prior-exposure check) is recorded for each of the six.
10. **Paper retention.** State the **retention period** for the original paper sheets, the session-conditions
    slips and their scans. The owner decided on 2026-11-25 that sheets, slips and scans are kept 12 months after the evaluation
    ends and destroyed together with the database and its backups, the consent text's period. The
    sheets and slips are scanned; the scans are stored with the private evidence, not in the repository.
    Any facilitator spray sheet that maps codes to identities is facilitator-only and stays outside the
    repository.
11. **Ambiguous marks.** An ambiguous mark on a sheet is entered as blank plus a flag, never resolved by
    guessing, and the count of such flags is reported.
12. **Reporting.** The pooled repeat benchmark is reported as 30 pairs excluding the holder and 36 including
    them (5 x 6 and 6 x 6 hidden repeats; the four-evaluator figures are 18 and 24). The holder split is the only
    split: no session carries the `group_shared_blotter` flag, so there is no second, flag-based report. Blind-baseline
    completeness lists skin-absent-by-design evaluators explicitly.

A gap flagged in the #221 review no longer applies. A sheet entered under the wrong evaluator was undetectable only when every
enrollment shared the blind code (group mode). With individual blotters every evaluator's codes are their own, so the
server's blind-code guard refuses such a sheet when the code is typed from the paper column (verified in code,
`confirm_blind_code`; P6.3 attacks it, see the [P6 gate](p6.md)). It remains a check on the code, not proof of who wrote
the sheet, and the facilitator still confirms the enrollment and paper record ID. (Amended 2026-11-27: for program
`v3.2` the codes are shared again, so this server guard no longer catches a wrong-evaluator sheet; see sign-off 19. The
facilitator's check is then the only guard.)

Holdouts do not open until a manager creates a checkpoint for the enrollment, in any program (merged in #214). In an
individual program (the F1 mode) that gate is per enrollment: an evaluator's holdouts open when that evaluator's own
checkpoint exists, `holdouts_open` is reported per row in the readiness view, and a holdout evidence time earlier than
that evaluator's own checkpoint is refused (422). The program-wide gate merged in #221 (`2bcd3cc`) applies only to
group blotter mode, which F1 does not use. Because the six evaluators sit the same sitting together, the facilitator
does not run a holdout sitting until all six checkpoints exist; that is a procedure, not an application rule. The server cannot see when a blotter was physically
smelled, so the facilitator must not spray or smell a holdout before the checkpoints exist (see the
[run sheet](../../facilitated-run-sheet.md#checkpoint-rule-no-holdout-is-sprayed-or-smelled-before-its-checkpoint-exists)).
The declaration should record when each enrollment's checkpoint was created, before any holdout observation. The
both-ways pooled repeat benchmark (`ml.reliability.pooled_reliability_both_ways`, merged in #213) only differs from
the plain pooled figure when a group blotter program exists, so F1 does not need it.

Software support for several of these items (shared-triple enrollment, non-blind flag, household reveal,
holdout gate, session-scoped screens, transcription timing, and group blotter mode (#220) with its safeguards
(#221), which F1 does not use) is tracked in the facilitated-format work items of
[PROJECT-PLAN.md section 11a](../PROJECT-PLAN.md#f1-facilitated-format-work-items-decided-2026-11-24).
Their merge is not evidence that P6.3 has rehearsed paper plus transcription in the six-person format, which
remains required before the P6 go decision.

P6 evidence must remain valid throughout F1. A material deployment, disclosure, identity, or
measurement change pauses the pilot until the affected readiness checks are repeated.

Only `proceed to D1` completes F1 for sequencing. A revise, extend, or stop decision leaves F1
open and keeps D1 blocked until a later reviewed pilot records `proceed to D1`.
